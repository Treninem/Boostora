# Boostora v3.2.5 — изоляция сбоев и регулярные резервные копии

Обновление поверх v3.2.4 без ломающей миграции и без отката функций.

Что улучшено:
- Telegram updates обрабатываются по одному: ошибка одного callback/message больше не выбрасывает остальные updates из полученного пакета;
- offset всё равно продвигается после проблемного update, поэтому зацикливания нет;
- promotions, реклама, напоминания, резервная копия и Boostore sync запускаются как независимые фоновые задания;
- исключение в одном фоновом задании не отменяет остальные задания текущего цикла;
- добавлены регулярные WAL-безопасные SQLite-копии во время долгой работы бота, а не только при перезапуске;
- периодический backup не сканирует и не копирует БД, пока свежая копия ещё не устарела;
- количество backup-файлов ограничено настройкой, старые копии удаляются автоматически;
- имена снимков получили микросекунды, поэтому быстрые перезапуски не перезаписывают копию с тем же временем.

Новые параметры:
```env
BACKGROUND_WORKER_INTERVAL_SECONDS=300
DB_BACKUP_INTERVAL_HOURS=12
DB_BACKUP_MAX_FILES=10
```

Для Bothost рекомендуются значения из `.env.example`. Основная БД по-прежнему находится в `BOT_DATA_DIR=/data`; таблицы и старые данные не удаляются.

# Boostora v3.2.4 — безопасная база и корректное завершение

Обновление поверх v3.2.3 без ломающей миграции и без отката функций.

Что улучшено:
- Bothost `SIGTERM` и обычный `SIGINT` теперь переводятся в единое мягкое завершение;
- polling, сетевой backoff и ожидание второго процесса сразу просыпаются при остановке;
- фоновый worker получает тот же stop-event и коротко завершается перед снятием lock-файла;
- резервные копии SQLite создаются через штатный `Connection.backup()`, поэтому учитывают данные из WAL;
- перед публикацией снимок проходит `PRAGMA integrity_check` и заменяется атомарно через `os.replace`;
- устранено копирование всей базы после каждой записи: legacy-зеркало теперь выключено по умолчанию и, при необходимости, ограничено интервалом;
- восстановление из старых расположений осталось доступно отдельно через `LEGACY_DB_RESTORE_ENABLED=1`;
- релиз-центр проверяет graceful shutdown и безопасность SQLite-снимков.

Новые параметры:
```env
LEGACY_DB_RESTORE_ENABLED=1
LEGACY_DB_MIRROR_ENABLED=0
LEGACY_MIRROR_INTERVAL_SECONDS=300
```

Для обычного Bothost оставь эти значения как в примере. Основная рабочая база по-прежнему хранится в `BOT_DATA_DIR=/data`; схема и старые данные не сбрасываются.

## Быстрый запуск на Bothost

1. Загрузить содержимое архива в корень проекта.
2. Создать `.env` на основе `.env.example`.
3. Указать `BOT_TOKEN`.
