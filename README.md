# Boostora v3.0.3

Telegram-бот Boostora для заданий, взаимного продвижения, рекламы во все чаты, внутренней валюты **Искры ✨**, VIP, trust-engine, кабинета заказчика, антифрода, админского центра решений, коммерческой аналитики владельца и релиз-центра.

## Что нового в v3.0.3

Это стабильный патч поверх **Boostora v3.0.2** без отката функций и без ломающей миграции.

- Поднята версия до **Boostora v3.0.3**.
- `APP_STAGE` изменён на `stable_patch_db_runtime_guard`.
- Усилена работа SQLite при живом боте:
  - `sqlite3.connect(..., timeout=30)`;
  - `PRAGMA busy_timeout = 5000`;
  - попытка включения `PRAGMA journal_mode = WAL` без падения, если режим недоступен.
- В stable gate добавлена проверка **Runtime-защита и очереди**.
- Релиз-центр теперь видит:
  - доступность подключения к базе;
  - примерный размер базы;
  - размер WAL-файла;
  - остаточный journal-файл;
  - зависшие input-сессии;
  - старые invoice-сообщения;
  - просроченные активные холды;
  - backlog рекламы во все чаты.
- Обновлены RU/EN тексты админки, коммерции владельца, релиз-центра и `/version`.
- Добавлен тест `scripts/stable_patch_v303_smoke_test.py`.
- Старые smoke-тесты обновлены под текущую версию v3.0.3.

## Главное про сохранение данных

Эта сборка продолжает стабильную ветку **v3.0.x** без ломающей миграции.

- Основной путь хранения на Bothost: `BOT_DATA_DIR=/data`.
- Старые пользователи, кошельки, задания, транзакции, VIP, рекламные кампании, антифрод-заметки, чаты и история решений должны сохраниться.
- Новых обязательных таблиц нет.
- Пользовательский архив не должен включать `storage`, `.db`, `.pyc`, `__pycache__`.

## Быстрый запуск на Bothost

1. Загрузить содержимое архива в корень проекта.
2. Создать `.env` на основе `.env.example`.
3. Указать `BOT_TOKEN`.
4. Указать `ADMIN_IDS`, первый валидный ID считается владельцем.
5. Оставить `BOT_DATA_DIR=/data`.
6. Команда запуска: `python3 main.py`.

## Живые проверки после обновления

1. `/start`, выбор языка, выбор роли, профиль, возвращение в меню без спама.
2. Кошелёк, пакет Искр, живой Stars-инвойс, история транзакций.
3. VIP-покупка и отображение VIP-статуса.
4. Создание задания шагами 1/3–3/3, предпросмотр, оплата.
5. Ускорение задания до быстрой или приоритетной цены.
6. Исполнитель берёт задание, отправляет proof, награда попадает в hold.
7. Админ разбирает спорную заявку через шаблоны и добавляет антифрод-заметку.
8. Live-аудит прав бота в тестовом чате/канале.
9. «Реклама во все чаты» с тестовым постом.
10. Коммерция владельца: оборот, резерв, маржа, обязательства.
11. Релиз-центр: stable gate, RC1-gate, guardrails, чек-лист, regression pack, целостность денег, проверка `/data` и runtime-защита.
12. Перезапуск бота после аварийного завершения: зависший lock не должен блокировать новый старт.
13. Проверить, что при параллельной активности бот не падает от `database is locked`.
