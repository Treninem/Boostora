# Boostora v4.0.0

Boostora — Telegram-бот и Mini App для продвижения, выполнения заданий, собственных кампаний и сети рекламных размещений. Основная внутренняя валюта — **Искры**. Версия 4.0.0 — глобальное обновление надёжности: рабочие механики v3.7 сохранены, а запуск, Mini App gateway, защита финансовых/рабочих операций, диагностика и контроль качества усилены отдельным v4-слоем.

## Что изменилось глобально

### 1. Новое runtime-ядро v4

`main.py` запускает `app.runtime_v4`, который сохраняет проверенный Telegram polling/background core и подключает новый Mini App gateway. Это позволяет обновлять защитный слой без переписывания работающих заданий, кампаний, кошелька и группового gate.

### 2. Защита от повторных операций

- mutations одного пользователя по-прежнему сериализуются на сервере;
- v4-клиент добавляет idempotency key к изменяющим Mini App-запросам;
- если сеть оборвалась после отправки действия, повтор использует тот же ключ до 180 секунд;
- сервер повторно отдаёт уже готовый успешный результат вместо второго выполнения одинаковой операции;
- ключ привязан к пользователю, операции и отпечатку payload;
- read-only запросы не попадают в idempotency cache.

Это особенно важно для кошелька, покупок, кампаний, заказов и других действий, которые нельзя безопасно выполнить дважды.

### 3. Rate limiting без хранения пользовательских данных

Gateway ограничивает слишком частые запросы отдельно для подтверждённого Telegram user id:

- чтение: по умолчанию 180 запросов / 60 секунд;
- изменения: по умолчанию 45 запросов / 60 секунд;
- лимиты и размер памяти настраиваются через `.env`;
- в памяти не сохраняются Telegram initData, токены, usernames или содержимое пользовательских запросов.

### 4. Resilient Mini App client

V4 gateway автоматически подключает `miniapp_example/v4-client.js` к существующему интерфейсу, не ломая основной `index.html`.

Клиент:

- сохраняет idempotency key только после транспортного сбоя;
- повторно использует его при ручном повторе того же действия;
- показывает понятное сообщение при offline/online;
- сообщает о временном rate limit;
- не делает автоматический повтор mutations.

### 5. Новая диагностика

Добавлены:

- `/health/live` — процесс жив;
- `/health/ready` — SQLite, Mini App assets, data directory, свободное место, startup guard и состояние worker;
- `/api/capabilities` — версия API и доступные механизмы gateway;
- `X-Request-ID` на ответах для поиска конкретной ошибки;
- owner-only `owner.system_health` теперь получает runtime/gateway telemetry без пользовательских payload.

### 6. Startup guard

Перед запуском Mini App проверяются:

- возможность записи в data directory;
- SQLite health;
- наличие Mini App;
- базовая корректность BOT_TOKEN;
- минимум свободного места на диске;
- HTTPS для публичного Mini App URL выводится как предупреждение.

### 7. Автоматический quality gate

GitHub Actions теперь автоматически выполняет:

- установку runtime dependencies;
- `compileall` для `app`, `tests` и `main.py`;
- v4 regression contract через стандартный `unittest`.

Новые изменения не должны попадать в `main`, если v4-контракт не собирается.

## Интерфейс

Сохраняется простая структура Mini App:

- **Главная** — состояние аккаунта и основные действия;
- **Работа** — задания, кампании и рекламная сеть;
- **Кабинет** — Искры, профиль, режимы, документы, дополнительные услуги и доступные инструменты.

Новые функции добавляются внутрь этих разделов, а не раздувают нижнее меню.

## Защита групп

Правило действует во всех Telegram `group` и `supergroup`, где присутствует Boostora.

- Пользователь один раз запускает Boostora в личке.
- До запуска его сообщения удаляются, а бот показывает кнопку запуска.
- После подтверждённого `/start` доступ действует во всех группах с Boostora.
- Повторный запуск для каждой группы не нужен.
- Автоматические публикации канала в связанную discussion group не блокируются.

Для строгой работы gate Boostora должна быть администратором группы с правом **удалять сообщения**.

## Автоматическая проверка заданий

Boostora автоматически проверяет только действия, которые Telegram позволяет надёжно связать с конкретным пользователем: подписку/вступление, заявку, реакцию, комментарий, сообщение в чате, поддерживаемое голосование и открытие целевой ссылки/публикации.

Для подписок, вступлений и реакций награда может удерживаться до повторной проверки. Снятие действия до окончания удержания отменяет только ещё не освобождённую награду.

## Экономика

- Stars используются для покупки Искр.
- Задания и внутренние услуги оплачиваются Искрами.
- Искры за выполнение заданий выдаются из заранее оплаченного бюджета заказчика.
- Бонусы хранятся отдельно и не превращаются автоматически в Stars.
- Ручные финансовые изменения владельца оставляют историю операции.

## Запуск

```bash
python3 main.py
```

Рабочие данные должны находиться вне кода:

```env
BOT_DATA_DIR=/app/data
DB_PATH=boostora.db
```

Настоящий `.env`, токены, API-ключи и рабочие SQLite-базы нельзя добавлять в GitHub.

## Проверка после деплоя

1. `/health/live` возвращает `ok=true`.
2. `/health/ready` возвращает `ok=true`.
3. `/api/capabilities` показывает API `4.0`.
4. `/start` работает в личном чате.
5. Mini App открывает **Главная / Работа / Кабинет**.
6. Одна тестовая операция с Искрами выполняется один раз.
7. При искусственном сетевом обрыве повтор mutation не создаёт вторую операцию.
8. Gate проверен в тестовой группе.
9. Owner diagnostics показывает v4 gateway/runtime.

## Совместимость данных

V4.0.0 не сбрасывает схему пользовательских данных и не требует миграции балансов. Балансы, кампании, задания, история, удержания, настройки и уже выданные допуски групп сохраняются. Перед крупным деплоем всё равно сделайте резервную копию `/app/data/boostora.db`.

Подробная инструкция для Bothost находится в `BOTHOST_START.md`.
