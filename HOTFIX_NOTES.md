# Boostora v3.3.0 — полный каталог Telegram и премиальная Mini App

Обновление поверх v3.2.9 без ломающей миграции базы.

Сделано:
- пользовательская витрина показывает только Telegram-услуги;
- все доступные Telegram-услуги разбиты по папкам и подпапкам;
- добавлена постраничная навигация, поэтому каталог больше не ограничен первыми 10 позициями;
- владелец может добавить или убрать одну услугу, подраздел, целую папку или сразу все Telegram-услуги;
- Facebook, Avito, 2GIS и другие площадки не попадают в пользовательскую витрину;
- тексты для обычных пользователей очищены от API, whitelist, ключей, синхронизации и внутренних инструкций владельца;
- техническая диагностика сохранена только в скрытом разделе владельца;
- все графические заглушки Mini App заменены; подключены 14 готовых премиальных изображений;
- изображения оптимизированы для быстрой загрузки без заметной потери качества;
- служебные панели Mini App удаляются из DOM для пользователей без соответствующей роли;
- исправлены повреждённые кнопки пагинации в админских списках чатов и пользователей.

Новых переменных `.env` нет. После обновления владелец открывает «Управление каталогом услуг», выполняет синхронизацию и нажимает «Добавить все Telegram-услуги» либо выбирает отдельные папки.

# Boostora v3.2.9 — Telegram callback/message hotfix

Исправлены две ошибки из живых логов Bothost:

1. `UserService.t() got multiple values for argument key` при `v18|boostore_check|balance`.
   Параметр функции перевода `key` переименован в `text_key`; поле `{key}` отчёта Boostore теперь передаётся безопасно.

2. `Bad Request: MESSAGE_TOO_LONG` при `v14|go|owner_release`.
   Релиз-центр переведён на компактную сводку; общий renderer дополнительно ограничивает случайно длинные экраны.

Дополнительно изменён порядок замены сообщений: новое сообщение отправляется до удаления старого. База данных и `.env` не меняются.
