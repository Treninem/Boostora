# Запуск Boostora v3.7.0 на Bothost

## 1. Деплой

Используйте ветку `main` репозитория `Treninem/Boostora`.

Команда запуска:

```bash
python3 main.py
```

Рабочие данные храните отдельно от кода:

```env
BOT_DATA_DIR=/app/data
DB_PATH=boostora.db
```

Не удаляйте `/app/data` при обычном обновлении.

## 2. Основные переменные

Значения берите из `.env.example` и задавайте в панели Bothost. Минимальная основа:

```env
BOT_TOKEN=ВАШ_ТОКЕН
ADMIN_IDS=2097006037
BOT_DATA_DIR=/app/data
DB_PATH=boostora.db
WEBAPP_ENABLED=1
WEBAPP_REQUIRED=1
WEBAPP_HOST=0.0.0.0
PORT=3000
WEBAPP_URL=https://boostorabot.bothost.tech
DROP_PENDING_UPDATES=0
CHAT_START_GATE_ENABLED=1
CHAT_START_GATE_NOTICE_COOLDOWN_SECONDS=15
```

Настоящие токены и ключи храните только в переменных окружения Bothost. Не загружайте рабочий `.env` в GitHub.

## 3. Права групп

Во **всех группах и супергруппах**, где Boostora должна запрещать сообщения до запуска бота, выдайте ей права администратора и право **удалять сообщения**.

Пользователь запускает Boostora один раз в личке. После подтверждённого `/start` доступ действует во всех группах с ботом; повторный запуск для каждой группы не нужен.

## 4. Проверка после деплоя

Сначала проверьте техническое состояние:

- `/health` отвечает без ошибки;
- `/health/ready` возвращает готовность SQLite и Mini App;
- `/start` работает в личном чате;
- Mini App открывается без ошибки;
- снизу видны только **Главная / Работа / Кабинет**;
- владелец видит закрытое управление, обычный пользователь — нет.

Затем проверьте одну тестовую группу:

1. пользователь, который не запускал Boostora, отправляет сообщение;
2. сообщение удаляется;
3. бот показывает предупреждение и кнопку запуска;
4. пользователь запускает Boostora в личке;
5. следующее сообщение в группе проходит.

## 5. SQLite и резервные копии

v3.7.0 использует WAL и усиленные транзакции. Перед крупным обновлением сохраните копию `/app/data/boostora.db`, но не переносите поверх неё пустую БД из архива.

Новая миграция пользовательских данных для v3.7.0 не требуется. Балансы, кампании, задания, история и допуски групп сохраняются.

## 6. Дополнительные Telegram-услуги

Раздел дополнительных услуг остаётся необязательным. Не включайте автоматические заказы до живого теста минимальной операции.

```env
BOOSTORE_ENABLED=1
BOOSTORE_AUTO_SYNC=0
BOOSTORE_AUTO_ORDER_ENABLED=0
```

После успешной проверки можно включать нужные автоматические функции отдельно.

## 7. Минимальная контрольная проверка v3.7.0

- `/health` — OK;
- `/health/ready` — ready;
- Mini App — 3 вкладки;
- двойной быстрый тап не создаёт двойную mutation;
- одна тестовая операция с Искрами проходит один раз;
- обязательный запуск в группе работает;
- background worker и диагностика владельца показывают живое ядро.
