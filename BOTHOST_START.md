# Запуск Boostora v4.0.0 на Bothost

## 1. Перед обновлением

Сохраните резервную копию рабочей базы:

```text
/app/data/boostora.db
```

Не удаляйте `/app/data` и не заменяйте рабочую БД файлами из репозитория.

## 2. Деплой

Используйте ветку `main` репозитория `Treninem/Boostora`.

Команда запуска:

```bash
python3 main.py
```

Рабочие данные:

```env
BOT_DATA_DIR=/app/data
DB_PATH=boostora.db
```

## 3. Основные переменные

Минимальная основа:

```env
BOT_TOKEN=ВАШ_ТОКЕН
ADMIN_IDS=ВАШ_TELEGRAM_ID
BOT_DATA_DIR=/app/data
DB_PATH=boostora.db
WEBAPP_ENABLED=1
WEBAPP_REQUIRED=1
WEBAPP_HOST=0.0.0.0
PORT=3000
WEBAPP_URL=https://boostorabot.bothost.tech
DROP_PENDING_UPDATES=0
CHAT_START_GATE_ENABLED=1
CHAT_START_GATE_NOTICE_COOLDOWN_SECONDS=15
```

V4 gateway имеет безопасные значения по умолчанию. При необходимости их можно переопределить:

```env
BOOSTORA_API_READS_PER_MINUTE=180
BOOSTORA_API_MUTATIONS_PER_MINUTE=45
BOOSTORA_API_RATE_WINDOW_SECONDS=60
BOOSTORA_IDEMPOTENCY_TTL_SECONDS=180
BOOSTORA_IDEMPOTENCY_CACHE_MAX=4096
BOOSTORA_RATE_BUCKETS_MAX=20000
```

Настоящие токены и ключи храните только в переменных Bothost. Рабочий `.env` в GitHub не загружайте.

## 4. Что делает v4 при запуске

Перед открытием Mini App gateway выполняется startup guard:

- проверяет запись в `/app/data`;
- проверяет SQLite;
- проверяет `index.html` и v4 client layer;
- проверяет базовую форму `BOT_TOKEN`;
- проверяет свободное место;
- предупреждает о неверном публичном URL.

Если `/health/ready` не готов, сначала исправьте указанный компонент, а не очищайте БД.

## 5. Проверка после деплоя

Проверьте по порядку:

1. `/health/live` — `ok=true`;
2. `/health/ready` — `ok=true`;
3. `/api/capabilities` — `api_version=4.0`;
4. `/start` — работает в личном чате;
5. Mini App — открывается без ошибки;
6. нижнее меню — **Главная / Работа / Кабинет**;
7. owner diagnostics — показывает gateway/runtime;
8. одна тестовая операция с Искрами — выполняется ровно один раз.

## 6. Проверка защиты повторной mutation

Для контрольного теста можно кратко оборвать сеть сразу после отправки безопасной тестовой операции и повторить действие после восстановления. V4 client сохраняет ключ только после транспортного сбоя, а сервер должен вернуть результат первой успешной операции вместо второго выполнения.

Не проводите такой тест на крупной покупке или реальном рекламном заказе.

## 7. Права групп

Во всех `group` и `supergroup`, где Boostora должна запрещать сообщения до запуска бота, выдайте ей права администратора и право **удалять сообщения**.

Пользователь запускает Boostora один раз в личке. После подтверждённого `/start` доступ действует во всех группах с ботом.

## 8. SQLite и резервные копии

V4 сохраняет WAL, усиленные транзакции и существующую схему данных. Миграция балансов для v4.0.0 не требуется.

Сохраняются:

- балансы и история;
- кампании и задания;
- удержания;
- настройки;
- доступы групп;
- owner/admin данные.

## 9. Дополнительные Telegram-услуги

До живой проверки минимального заказа оставляйте:

```env
BOOSTORE_ENABLED=1
BOOSTORE_AUTO_SYNC=0
BOOSTORE_AUTO_ORDER_ENABLED=0
```

Автоматическое создание заказов включайте только после отдельного успешного теста провайдера.
