# Запуск Boostora v3.6.4 на Bothost

## 1. Архив

Для нового деплоя используйте `Boostora_v3.6.4_RUNTIME.zip`. Распакуйте его в корень репозитория.

## 2. Команда запуска

```bash
python3 main.py
```

## 3. Основные переменные

Скопируйте значения из `.env.example` в панель Bothost. Минимально необходимы:

```env
BOT_TOKEN=ВАШ_ТОКЕН
ADMIN_IDS=2097006037
BOT_DATA_DIR=/app/data
DB_PATH=boostora.db
WEBAPP_ENABLED=1
WEBAPP_REQUIRED=1
WEBAPP_HOST=0.0.0.0
PORT=3000
WEBAPP_URL=https://boostorabot.bothost.tech
DROP_PENDING_UPDATES=0
CHAT_START_GATE_ENABLED=1
CHAT_START_GATE_CHAT_REF=@Boostorachat
CHAT_START_GATE_CHAT_LINK=https://t.me/Boostorachat
CHAT_START_GATE_START_PARAMETER=chat_access
CHAT_START_GATE_NOTICE_COOLDOWN_SECONDS=15
```

## 4. Права во всех группах

Для строгого режима **в каждой группе и супергруппе**, где находится Boostora, сделайте бота администратором и включите право **удалять сообщения**. Без этого права Boostora не сможет гарантированно удалить сообщения незапустивших пользователей.

`@Boostorachat` по-прежнему проверяется при запуске как основная контрольная группа. Для остальных групп права администратора с удалением сообщений нужно выдать при добавлении Boostora. Само правило блокировки применяется ко всем `group` и `supergroup`.

Пользователь запускает Boostora один раз. После подтверждённого `/start` доступ действует во всех группах с ботом. Уже выданный доступ из v3.6.2/v3.6.3 сохраняется.

Для необязательного раздела дополнительных услуг:

```env
BOOSTORE_ENABLED=1
BOOSTORE_API_URL=https://boostore.ru/api/v2
BOOSTORE_API_KEY=ВАШ_КЛЮЧ
BOOSTORE_DEFAULT_MARKUP_PERCENT=35
BOOSTORE_AUTO_SYNC=0
BOOSTORE_AUTO_ORDER_ENABLED=0
```

Настоящие ключи храните только в переменных Bothost. Не помещайте их в код, архив или GitHub.

## 5. Первый запуск

После деплоя проверьте:

- `/health` отвечает без ошибки;
- `/start` показывает соглашение;
- отказ блокирует функции;
- принятие открывает Mini App;
- владелец видит закрытое управление;
- обычный пользователь не видит административные разделы.

## 6. Живая проверка платежей

Сначала купите минимальный пакет Искр. Stars должны начислить Искры один раз, а не оплатить рекламу или внешнюю услугу напрямую.

## 7. Живая проверка дополнительных услуг

1. При необходимости включите дополнительный каталог в закрытом управлении и синхронизируйте его.
2. Убедитесь, что основной экран по-прежнему открывает задания, кампании и рекламную сеть, а дополнительный каталог находится в конце навигации.
3. Выберите конкретную услугу как обычный пользователь и проверьте актуальную цену с наценкой.
4. Создайте один минимальный тестовый заказ.
5. Только после успешного теста включите `BOOSTORE_AUTO_ORDER_ENABLED=1`.

## 8. Проверка рекламной сети

Добавьте бота администратором в тестовый канал или чат от 100 участников. Выдайте права на публикацию и создание пригласительных ссылок. Проверьте автоматическое появление площадки, расписание, публикацию, отслеживание и реакцию системы на снятие прав.

## 9. База и резервные копии

Рабочая БД должна находиться в `/app/data`. Не удаляйте каталог данных при обычном обновлении. Перед крупным обновлением сохраните резервную копию.
